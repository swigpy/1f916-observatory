# Round 1 product and architecture decision

Date: 11 September 2026. Author: 1F916 Observatory contributors, implemented and drafted with OpenAI Codex.

## Product

A narrative observatory for people who have never visited 1F916. The entry point is three selected stories, not a ranked feed. Every card answers what happened, why it matters, who is involved and what changed. Each dossier offers a chronology, contrasting positions, public contributor context and primary evidence.

The interface is English because this is a public international bounty. The visual direction is a restrained field journal: dark blue masthead, serif headlines, cool white reading surfaces, warm evidence accents and compact linked source notes. No decorative graph, model-family ranking, graveyard or KPI wall.

## Architecture

- Static multipage HTML generated by Node's standard library. No production dependency, client framework, database, application server, account, analytics, model API or wallet.
- Normal links and native details/summary do the core work without JavaScript. The initial render makes zero requests to 1F916. Source text is already rendered safely into the dated edition.
- Optional enhancement checks `/api/pulse` once on request, at most once per minute. It reports whether the board moved; it does not refresh or validate the story. An API failure leaves all editorial pages intact.
- Files under `data/raw/` are captured public source records. Citizen profiles are intentionally projected to public identity and three recent post headers. Model declaration is labelled as testimony.
- `src/model.mjs` contains deterministic ordering, explicit-reference extraction and scoped reply connections. `data/editorial/stories.json` contains the selection, titles, explanations, roles and perspectives.
- Capture SHA-256 hashes bind source response bytes. They are integrity checks, not cryptographic authentication of the source. The sequence of requests is not an atomic snapshot.
- Node test runner, jsdom, axe-core and acorn provide dev-only verification. Vite is used only for the supervised local browser inspection; it does not ship to production. Runtime JS is small and optional.
- `npm run snapshot` fetches a candidate capture into ignored local runtime storage. It cannot overwrite the reviewed edition. A thread that outgrows the currently handled first-page cap stops the capture for explicit pagination work.

## Boundaries

The sole network module accepts an operation and a validated identifier; no arbitrary URL, headers or request options. It hard-codes GET, credential omission, redirect refusal, a 12-second deadline and an 8 MB streamed byte cap. Its five operations are pulse, post, comment, citizen and grant. Public discovery found many more read surfaces; unused surfaces are deliberately not runtime capabilities.

Citizen text is never executable markup. The page has no form, input, textarea, select, contenteditable, wallet entry, account flow or field accepting any secret. Source URLs are generated from trusted origins and validated identifiers; citizen-provided URLs in body text are not made into links. A strict meta CSP applies on GitHub Pages; an equivalent `_headers` file adds hosting-supported header protections. The CSP restricts destinations, not HTTP methods: method enforcement is in the code and automated audit.

This checkout is separate from every BC repository and has no BC secrets or publisher integration. Readable public BC activity would be ordinary source material; no prior chat or private BC material is used in this edition.

## Hosting and review

GitHub Pages is sufficient: all normal paths use relative assets and work below a repository prefix. A Pages workflow is prepared; Node generates `dist`. A separately hosted Sites preview provides an immediate working artifact. The connected GitHub toolset has no repository-creation operation and no preexisting `swigpy/1f916-observatory` was accessible (404); the public GitHub repository and normal PR route remain a delivery gate until the owner creates/connects it. No code is pushed directly to a GitHub main branch.

## Explicit omissions

No full economy explorer, social graph, 3D world, model-family comparisons, automated AI summarization, scheduled refresh, publication to 1F916, submission or payout operation. No claim of independently verified cryptography. No assumption that selected threads represent the entire society.

## Next product test

Give the site to a newcomer for 60 seconds and ask: what happened, why does it matter, who disagrees, and which link would you use to check? Measure this with people before expanding the taxonomy. Next add a cultural or playful story so this does not become an observatory only of audits, then build a dated editorial update/diff process.

## Superseding direction: private iteration

The owner has created the repository as private and requested iteration before public sharing. The preview is now owner-only. Do not make either surface public without a new explicit release decision. Personal identity is omitted from the interface and distributed source; historical private Git author metadata is not rewritten.

The first three stories were a one-off prototype selection by OpenAI Codex, not a daily editorial service or neutral sample. Selection policy, editorial ownership, update cadence and maintenance remain open design decisions. The next product iteration must make dossier explanations understandable to someone with no platform or technical background before expanding automation.
